# 课堂互动模块页面布局优化方案

> 适用范围：教师端 `TeacherPage.tsx` 的「课堂问答」「课堂互动」模块、学生端 `StudentPage.tsx` 的「课堂互动」模块，以及页面整体框架。
> 目标：消除无效留白、压缩纵向滚动、强化互动功能的视觉层次与易用性，并保证在 xs(手机) / sm / md / lg / xl 各断点下均良好适配。

---

## 一、当前布局空间浪费点分析

### 1. 教师端 · 课堂互动模块（`TeacherPage.tsx` 重构前约 4296–4452 行）

| 区域 | 问题 | 影响 |
| --- | --- | --- |
| 左栏顺序 | 「待审核发言」卡片排在「互动课堂」选择框**之前**。教师进模块第一眼看到的是审核队列，而选择课堂才是首要操作。 | 操作动线反直觉，新教师易困惑。 |
| 教师输入区 | 「教师互动消息」文本框 + 「发送互动消息」按钮放在**左栏底部**，与右侧聊天流完全分离。 | 发消息时视线在左栏与右栏之间大幅跳跃；聊天面板不像聊天，输入与消息流割裂。 |
| 聊天面板高度 | `minHeight:360, maxHeight:600` 固定值；左栏无对应等高约束。 | 当屏幕更高时聊天区被 600 上限截断，留白或被迫二次滚动；左右两栏高度不对齐。 |
| 内边距 | 卡片 `p:1.5`、聊天 `p:1.5` 尚可，但输入区与聊天分离导致整体信息密度偏低。 | 单屏可见留言条数少。 |

### 2. 教师端 · 课堂问答模块（`TeacherPage.tsx` 约 3584–4283 行）

| 区域 | 问题 | 影响 |
| --- | --- | --- |
| 题目列表 Paper | `minHeight:220` 强制占位；题目以**单列长列表**呈现（每条 `borderBottom` + 标题 + 两按钮）。 | 题目少时大片空白；题目多时纵向巨长，必须滚动才能看到统计/作答。 |
| 统计 Paper | `minHeight:220` 同样强制占位，且未选中题目时仅一行提示却占 220px。 | 明显留白浪费。 |
| 卡片内边距 | 多个 Paper 使用 `p:2`（16px），信息密度偏低。 | 同上。 |
| 外层间距 | 模块外层 `Stack spacing={2.5}`（20px）。 | 略松。 |

### 3. 学生端 · 课堂互动模块（`StudentPage.tsx` 约 1241–1332 行）

| 区域 | 问题 | 影响 |
| --- | --- | --- |
| 卡片宽度 | 整体 `Card sx={{ maxWidth: 760 }}` 居中。 | 在 ≥1280px 屏幕上左右各约 250px 空白，聊天信息密度低。 |
| 聊天高度 | `minHeight:400` 固定；发送区在卡片底部独立一行。 | 与教师端类似，固定高度在超大屏上不自适应。 |
| 一致性 | 学生端为单列，结构本身紧凑，主要问题在「宽度未利用」而非纵向。 | — |

### 4. 页面整体框架（`TeacherPage.tsx` 约 1917–1978 行）

- 左侧导航 260px（`md` 起 `sticky`），右侧内容区 `<Stack spacing={3}>`。整体框架合理，**本次不改动**，仅在模块内部做密度优化。
- 主题 `h2` 已覆写为 `1.25rem`（20px），标题尺寸合理，不是浪费来源（已确认 `styles/theme.ts`）。

## 二、重设计布局

### 2.1 教师端 · 课堂互动（改为「控制栏 + 聊天面板」双栏）

```
┌──────────────────────────────────────────────────────────────┐
│ 课堂互动  · 学生完成签到后可发言；教师可随时暂停。   [状态 Alert] │
├───────────────────────┬──────────────────────────────────────┤
│ 左栏 (md=4) 控制区     │ 右栏 (md=8) 聊天面板                  │
│                       │  ┌────────────────────────────────┐  │
│ [互动课堂 ▾ Select]   │  │ 消息流（flex:1, overflow:auto） │  │
│ (✅开启/⏸暂停) Switch │  │   🟦 老师 …                     │  │
│                       │  │   🟩 学生 …                     │  │
│ ┌ 待审核发言  [刷新]┐  │  │   🟩 学生 …                     │  │
│ │ ⚠ 待审核 张三     │  │  │   …                            │  │
│ │ 内容… [放行][忽略]│  │  └────────────────────────────────┘  │
│ │ ⚠ 待审核 李四     │  │  ┌────────────────────────────────┐  │
│ └───────────────────┘  │  │ [教师互动消息………]   [发送]     │  │
│  (flex:1 占满剩余高度)  │  └────────────────────────────────┘  │
└───────────────────────┴──────────────────────────────────────┘
```

**关键改动**
- 左栏顺序改为：**互动课堂选择 → 发言开关 → 待审核发言**（符合「先选课堂 → 再控开关 → 处理审核」的操作动线）。
- 教师消息输入区（文本框 + 发送按钮）**下沉到聊天面板底部**，作为 sticky footer（`borderTop` 分隔 + `background.paper` 底色），聊天面板变成真正的「消息流 + 输入区」结构。
- 聊天面板改为 `flex` 纵向布局：消息流 `flex:1; overflow:auto`，输入区固定底部；高度用 `minHeight:420 / maxHeight: calc(100vh - 200px)` 自适应视口，而非死值 600。
- 左栏用 `height:100%` + 待审核卡片 `flex:1; minHeight:0; overflow:auto`，使左右两栏等高，审核列表在自身区域内滚动，不再撑高整页。

### 2.2 教师端 · 课堂问答（列表网格化 + 去强制留白）

```
┌─────────────────── 左栏(md=5) 出题表单 ───────────────────┐    ┌── 右栏(md=7) ──┐
│ 问答课堂 ▾ │ 题型 ▾  分值 │ 题目标题 │ 题干 │ 截止时间 …  │    │ 加分与导出(紧凑) │
│ 选项 A/B/C… │ 发布问题                                    │    │ ┌─题目卡片─┐┌─题目卡片─┐ │
│                                                            │    │ │标题/类型 ││标题/类型 │ │
│                                                            │    │ │[统计][作答]│[统计][作答]│ │
│                                                            │    │ └─────────┘└─────────┘ │
│                                                            │    │ 统计 / 学生作答(按需展开) │
└────────────────────────────────────────────────────────────┘    └──────────────────┘
```

**关键改动**
- 题目列表由「单列长列表」改为 `Grid container` + `item xs={12} sm={6}` 的**双列卡片网格**（sm 及以上两列，xs 单列），相同纵向空间内可见题目数翻倍，显著减少滚动。
- 移除题目列表、统计两张 Paper 的 `minHeight:220` 强制占位；卡片内边距 `p:2 → p:1.5`，模块外层 `spacing:2.5 → 2`。
- 单张卡片：标题 `noWrap` + `title` 悬浮提示，避免长标题换行撑高；按钮行收紧为 `spacing:0.5`。

### 2.3 学生端 · 课堂互动（宽度利用）

- 将「课堂互动」卡片的 `maxWidth:760` 放宽或去除，让聊天面板占满内容列宽，提升大屏信息密度（其他卡片维持 760 以保证整体节奏一致，或一并放宽——见第 4 节取舍）。
- 聊天高度由固定 `minHeight:400` 改为 `minHeight: 420 / maxHeight: calc(100vh - 200px)`，与教师端对齐。
- 发送区保持「文本框 + 发送按钮」单行，结构已紧凑，仅需跟随高度规则统一。

## 三、组件尺寸与间距刻度

统一采用 4px 基准栅格（MUI `spacing` 单位 = 8px，下列以 spacing 值表示）：

| 项 | 原值 | 优化值 | 说明 |
| --- | --- | --- | --- |
| 模块外层 Stack spacing | 2.5 / 3 | 2 | 标题与内容、卡片间更紧凑 |
| 卡片内边距 `p` | 2 (16px) | 1.5 (12px) | 信息密度提升，仍留白舒适 |
| 双栏 Grid `spacing` | 1.5 / 2 | 1.5 | 保持 |
| 聊天面板 minHeight | 360 (固定) | 420 | 起步可视条数 |
| 聊天面板 maxHeight | 600 (固定) | `calc(100vh - 200px)` | 自适应视口，避免死值截断 |
| 待审核卡片 | maxHeight:200 独立 | `flex:1; minHeight:0; overflow:auto` | 随左栏等高，自身滚动 |
| 题目卡片 | 单列 / `borderBottom` | 双列网格卡片 (sm=6) | 密度翻倍 |
| 教师输入区位置 | 左栏底部独立 | 聊天面板 sticky footer | 视线不跳跃 |
| 发送按钮文案 | 「发送互动消息」 | 「发送」(footer 内) | footer 空间有限，精简文案 |
| 输入框行数 | `minRows:2` | `minRows:1 / maxRows:4` | 默认一行，长文本自动增高 |

**字号/层级（沿用主题，不做破坏性调整）**
- 模块主标题：`h2` = 1.25rem / 700（已是合理值）。
- 卡片小标题：`fontWeight:700`，`fontSize:0.9rem`。
- 正文：`body2` (0.875rem) 次级文字 `text.secondary`。
- 按钮：`textTransform:none`，主操作 `variant=contained` 蓝色主色，次级 `outlined`。

## 四、响应式适配策略

断点（沿用 `theme.ts`）：`xs:0 sm:600 md:960 lg:1200 xl:1536`。

| 断点 | 课堂互动 | 课堂问答 | 学生互动 |
| --- | --- | --- | --- |
| `xs` (<600) | 双栏 `Grid` 自动堆叠为单列：先控制区，后聊天面板（聊天 `minHeight:420` 仍可用） | 左表单单列；题目卡片 `xs=12` 单列 | 单列，聊天占满宽度 |
| `sm` (600+) | 仍单列（控制区窄不适合并排），聊天 `maxHeight` 限高 | 题目卡片变 `sm=6` 双列 | 同上 |
| `md` (960+) | **双栏展开**：控制区 `md=4` / 聊天 `md=8`，左栏 `sticky` 等高 | 表单 `md=5` / 右栏 `md=7` 双列 | 卡片放宽至占满内容列 |
| `lg/xl` | 维持 `md` 比例；聊天 `maxHeight` 随视口增大，可见条数更多 | 同 `md` | 同 `md` |

**关键适配手段**
- 全部双栏均用 MUI `Grid` 的 `item xs={12} md={n}`，天然在窄屏堆叠、宽屏并排，无需手写媒体查询。
- 聊天面板用 `flex` + `overflow:auto` + `maxHeight: calc(100vh - 200px)`，在任何高度下都只滚动消息流，输入区常驻底部可见。
- 左栏控制区 `height:100%` + 待审核卡片 `flex:1; minHeight:0`，保证窄屏堆叠时也能在自身高度内滚动，不撑破布局。
- 输入框 `minRows/maxRows` 自适应，移动端长文本不溢出。

## 五、视觉层次与易用性

1. **主从清晰**：聊天面板（右栏，更宽 `md=8`）是视觉主体；左栏控制区为从属，用更轻的 `outlined` 卡片包裹。
2. **操作动线**：选课堂 → 控开关 → 看消息/审留言 → 发消息（footer），符合教师心智模型。
3. **状态可视**：顶部 `Alert` 用 success/warning + emoji 直观表达「发言开/关」与待审核数量；待审核卡片独立高亮（`rgba(255,168,0,0.08)` 底色）区别于普通消息。
4. **输入反馈**：footer 文本框带 `0/300` 计数与禁用态（空内容不可发），降低误操作。
5. **密度与呼吸感平衡**：卡片 `p:1.5`、间距 `spacing:2` 在紧凑与可读间取平衡，不追求极端压缩导致拥挤。
