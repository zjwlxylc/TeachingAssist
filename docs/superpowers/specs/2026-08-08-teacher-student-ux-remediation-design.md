# 教师端与学生端交互整改设计

## 背景与边界

本轮工作属于真实机房试点前的反馈驱动缺陷修复，不启动新的产品 Outcome。现有
`TeacherPage.tsx`、`StudentPage.tsx` 和 `docs/interaction-layout-optimization.md`
中的未提交改动是已确认的实施基线，必须保留。

默认只修改前端及本轮设计、计划文档；不改变后端 API、SQLite、业务规则、认证、AI
Provider 或部署方式，不升级 React、Vite、MUI、Node 或其他依赖，不提交或 push。

## 现状证据

- 在 390×844 视口中，学生端 8 项纵向导航占据首屏大部分空间，签到内容需要明显下滚。
- 在同一视口中，教师端 12 项纵向导航与完整迁移、目录明细形成超长页面，常用状态被技术细节淹没。
- 学生端在没有选择课堂时仍显示“连接已断开”，把“尚未建立连接”误报成故障。
- 教师侧栏按钮的可访问名称来自 Tooltip 描述，而不是可见功能名，屏幕阅读器难以建立功能映射。
- 固定的“开源仓库”入口在窄屏覆盖导航和状态提示，不属于课堂任务的核心操作。
- 教师系统卡片直接显示 `ok`、`development` 等内部值，不符合教师使用语言。
- 基线中的教师互动双栏、聊天固定输入区、问答双列卡片和学生聊天自适应高度方向正确，继续保留。

## 方案比较

### 方案 A：全站视觉重构

统一重做页面、导航和视觉系统。覆盖面最大，但会突破当前试点缺陷修复边界，回归风险高，不采用。

### 方案 B：只输出审查清单

不修改代码。风险最低，但不满足“做出改善”的目标，不采用。

### 方案 C：全面审查、聚焦整改（采用）

保留桌面端工作台结构和现有功能，只修复高影响、结论明确的导航、状态反馈、信息层级和移动端遮挡问题。
该方案对业务零侵入，能用浏览器观察和构建命令直接验证。

## 交互设计

### 响应式功能导航

- `md` 及以上继续使用现有左侧固定导航，保持教师机桌面操作习惯。
- `md` 以下隐藏完整侧栏，改为页面内容顶部的单个 MUI Select：教师端标签为“教师功能”，学生端标签为“学生功能”。
- Select 下面显示当前功能说明；未读计数附在选项文本中，切换功能时沿用现有清零规则。
- 教师桌面 Tooltip 使用描述关系而不是覆盖按钮名称，使按钮可访问名称与可见功能名一致。

### 学生端状态反馈

- 只有选定有效课堂后才显示 WebSocket 连接提示；未选择课堂不再误报断线。
- 没有活动课堂时，在选择框附近显示明确空状态，提示学生可刷新或输入教师提供的课堂 ID。
- 提交签到期间禁用主按钮、显示进度并设置 `aria-busy`，防止重复提交。
- 不改变签到、注册申请、离线缓存或课堂切换逻辑。

### 教师端信息层级

- 将服务状态、数据库完整性和运行环境内部值映射为“正常”“开发环境”等教师可理解文本。
- 数据库位置和 U 盘识别继续直接可见；迁移列表和初始化目录收进默认折叠的“查看技术详情”，需要排障时仍可展开。

### 移动端非核心入口

- 固定“开源仓库”入口在 `xs` 视口隐藏，在 `sm` 及以上保持现状，避免遮挡课堂操作。

## 无障碍与响应式要求

- 移动功能选择器必须具有可访问标签，并可使用键盘完成切换。
- 教师桌面侧栏按钮的可访问名称必须等于可见功能名，Tooltip 只作为描述。
- 390px 宽度下不得产生页面级横向滚动，主内容必须在首屏导航后立即出现。
- 保持 MUI 既有焦点样式、颜色语义和最小触控面积，不新增仅靠颜色表达的状态。

## 验证设计

- 先用 Playwright 浏览器断言记录 RED：移动功能选择器不存在、学生空状态不存在、无课堂时误报断线、签到提交缺少进行中状态、移动端仓库入口可见、教师技术详情未折叠、教师导航无正确可访问名称。
- 每组最小修改后重新运行对应断言至 GREEN。
- 在 1440×900 和 390×844 下回归教师端、学生端全部导航入口，检查页面级横向溢出、控制台错误和主要空状态。
- 运行 `npm.cmd run build`，接受仓库已有的主 chunk 体积警告，但不得新增编译错误。
- 运行 `python scripts/ale.py focused --target frontend` 和 `git diff --check` 作为最终仓库验证。

## 明确不做

- 不拆分两个大型页面，不新增功能，不调整后端或数据库。
- 不重做颜色、字体、品牌和桌面信息架构。
- 不处理需要真实教师或学生决策才能确认的流程问题，只在最终报告中列为后续试点观察项。
