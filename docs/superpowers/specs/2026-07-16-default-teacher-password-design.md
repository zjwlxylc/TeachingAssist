# 教师缺省密码设计

## 目标

- 新建数据库中的教师账户自动使用缺省密码 `test123`。
- 将本机现有教师账户密码一次性重置为 `test123`。
- 教师以后修改密码时，系统启动不得再次覆盖。
- 本机数据库文件不进入 Git 提交。

## 方案

在应用配置中增加认证配置项 `auth.default_teacher_password`，缺省值为 `test123`。数据库迁移和启动检查完成后，认证服务检查教师账户：仅当 `password_hash` 为空时，使用现有 PBKDF2-SHA256 算法生成带随机盐的哈希并写入数据库。

本机现有数据库已经设置过密码，因此启动初始化不会覆盖它。实施时单独执行一次受控重置：写入 `test123` 的新哈希，清除失败次数与锁定时间，并撤销现有教师登录令牌。该操作只修改本机数据库，不提交数据库文件。

## 代码边界

- `backend/app/core/config.py`：增加认证配置模型。
- `config/default.yaml`：声明缺省教师密码。
- `backend/app/services/auth.py`：增加“仅在未设置时初始化”和“显式重置”能力。
- `backend/app/services/startup.py`：在数据库迁移完成后调用缺省密码初始化。
- 后端测试：覆盖空密码初始化、已有密码保持不变、显式重置及旧令牌撤销。

不修改学生认证、前端登录表单、课堂业务模块和数据库表结构。

## 数据流

1. 应用启动并完成 SQL 迁移，确保教师账户存在。
2. 启动服务读取 `auth.default_teacher_password`。
3. 教师密码为空时写入哈希；已有哈希时不做任何写操作。
4. 教师通过现有登录接口使用 `test123` 登录。
5. 本机现有账户通过一次性重置操作切换到 `test123`，旧令牌立即失效。

## 错误处理与安全

- 缺省密码长度继续受现有不少于 6 位的约束。
- 数据库仅保存随机盐 PBKDF2 哈希，不保存明文密码。
- 初始化过程保持幂等，多次启动不会改变已有密码。
- 显式重置不绑定到公开 HTTP 接口，避免局域网用户触发重置。

## 验证

- 先写失败测试，证明当前新数据库不会自动设置 `test123`。
- 实现后验证新数据库可用 `test123` 登录。
- 验证已有自定义密码在重启后仍可用，`test123` 不会覆盖它。
- 验证显式重置后 `test123` 可登录，旧密码和旧令牌失效。
